SOJOURNER

MAP VIEWER · MINECRAFT · JAVA + BEDROCK

Reads a Minecraft world save and renders it in full — terrain, structures, ore veins, chests, villagers, loot — pulled directly from the world files. Nothing else shows you all of it.

// what's missing everywhere else

Every other map tool stops at the terrain.

Beautiful hills and oceans — and not a word about the chest you forgot, the villager three biomes over, the spawner under your base. Seed tools go the other way: a flawless generated world you don't actually have, nothing you built, nothing alive. Sojourner reads the world you actually have — the living world, blocks and builds and mobs and loot and all, straight off the save.

// what you get

The living world, not just its skin.

Open a save and it draws what's there — the real blocks you placed, the biomes and structures from the seed, the ore veins, the caves. Then the part nobody else bothers with:

  • Every chest and exactly what's in it. Spawners, signs, banners, beehives, brewing stands — all of it, grouped and searchable.
  • Every villager and what they do. Mobs, item frames, minecarts, bosses — placed where they actually stand.
  • Beds, workstations, bells. The bones of a settlement, straight off the save.
  • And the seed side — biomes, structures, slime chunks, ore veins, cave mode, relief.

On Java and Bedrock both. The chest-and-villager depth is the part every fast, pretty renderer skips entirely.

// what makes it different

Built for depth, not speed.

Not a seed-hunting tool — it shows you the world you already have. Not chasing render-benchmark numbers either — it's chasing completeness: every chest, every villager, every structure, read straight off your save. That's the depth every other viewer skips.

// standing on their shoulders

Built on other people's hard-won work.

Sojourner didn't solve Java's world generation or Bedrock's storage format from scratch — these projects already had, for free, and let anyone build on top. That's the only reason any of this exists.

  • cubiomes (Cubitect, MIT) — the actual Java world-generation math. Every biome, structure, and seed calculation on this page runs through it. License
  • LevelDB (Google, BSD-3-Clause) — the database format Bedrock worlds are stored in. Without it there's no Bedrock support at all. License
  • Snappy (Google, BSD-3-Clause) — the compression LevelDB runs on. License
  • Leaflet (BSD-2-Clause) — the map engine under every pan and zoom, including the live demo above. License
  • Tauri (MIT / Apache-2.0) — the desktop shell that makes a small, fast, no-telemetry app possible. MIT · Apache-2.0
